HOW TO ADD A NAVIGATION MARKER
================================

This guide applies to both the parish and house navigation maps.

Important concepts
------------------

1. A graph node describes a physical position on the floor plan.
2. A graph edge describes a valid walking path between two nodes.
3. A destination is a place a visitor can select in the navigation UI.
4. A marker connects a printed image to one graph node and one scanning
   direction.
5. targets.mind is the compiled recognition database for every marker image in
   that map. It is not generated automatically by the SVG generator.

Never reorder existing markers. Marker order is also the MindAR target index:

  P00 = target index 0
  P01 = target index 1
  ...
  P16 = target index 16

Always append a new marker at the end. Reordering markers can make an installed
marker identify the wrong location.


PART 1: ADD THE MAP POSITION
----------------------------

For the parish, edit:

  src/features/ar-navigation/maps/parish/layout.ts

For the house, edit:

  src/features/ar-navigation/maps/house/layout.ts

Add a unique node ID and its position. Coordinates are relative to the drawing,
not GPS coordinates. In the current maps, x increases toward the right and y
increases toward the bottom.

Example:

  new_room_entry: {
    name: "New Room entrance",
    floorId: "church",
    x: 12,
    y: 18,
  },

If the physical position already has a graph node, reuse it instead of creating
a duplicate node. Main Church reused the existing c_church node.


PART 2: CONNECT THE WALKING PATH
--------------------------------

For the parish, edit:

  src/features/ar-navigation/maps/parish/graph.ts

For the house, edit:

  src/features/ar-navigation/maps/house/graph.ts

Add an edge only where a person can physically walk. Do not connect nodes
through walls, furniture, locked doors, or staff-only areas.

Parish example:

  passage("existing_hall", "new_room_entry", 4),

House example:

  { from: "existing_hall", to: "new_room_entry", distance: 4 },

Use access: "staff" for a staff-only parish connection. Public navigation
filters those edges out.


PART 3: ADD THE DESTINATION, IF SELECTABLE
------------------------------------------

Only do this when the place should appear in the visitor destination list.

Parish file:

  src/features/ar-navigation/maps/parish/destinations.ts

House file:

  src/features/ar-navigation/maps/house/destinations.ts

Example:

  {
    id: "new-room",
    name: "New Room",
    nodeId: "new_room_entry",
  },

A checkpoint marker does not have to be a destination. Hallway and stair
markers may exist only to recalibrate the route.


PART 4: APPEND THE MARKER DEFINITION
------------------------------------

Parish file:

  src/features/ar-navigation/maps/parish/markers.ts

Append a new item at the END of the placements array:

  [
    "new_room_entry",
    90,
    "Outside the New Room entrance. Face right toward the doorway.",
  ],

The parish code and target index are generated from its position in the array.
The next marker after P16 will automatically become P17.

House file:

  src/features/ar-navigation/maps/house/markers.ts

Append a new object at the END of markerManifest:

  {
    nodeId: "new_room_entry",
    departureNodeId: "public_hall_outside_new_room",
    name: "New Room entrance",
    facing: 90,
    placement: "Outside the New Room entrance. Face right toward the doorway.",
  },

House marker codes are generated by array position. The next marker after H09
will automatically become H10.


FACING VALUES
-------------

Facing is the direction the visitor faces WHILE SCANNING the marker. It is
clockwise from the top of the floor-plan drawing:

    0 = toward the top of the drawing
   90 = toward the right
  180 = toward the bottom
  270 = toward the left

This is not a compass bearing. The application uses this value to rotate the AR
arrow relative to the route.

Mount the physical marker upright and make sure visitors can scan it from the
documented side.


ARRIVAL NODE VERSUS DEPARTURE NODE
----------------------------------

nodeId is the point that confirms arrival at the marker or destination.

departureNodeId is the public-side point where route calculation begins after
the visitor scans the marker and travels somewhere else.

For parish markers, the existing marker nodes are already public-side boundary
positions, so departureNodeId currently equals nodeId.

For a doorway scanned from a corridor, departureNodeId should normally be the
corridor-side node. This prevents incorrect instructions such as "Turn around"
when the visitor is already standing outside the room.

If no corridor-side node exists, add one to layout.ts and graph.ts first.


PART 5: GENERATE THE SVG AND PRINT PACK
---------------------------------------

From the frontend directory, run one of these commands:

  cd frontend

  node src/features/ar-navigation/maps/parish/generateMarkers.mjs

or:

  node src/features/ar-navigation/maps/house/generateMarkers.mjs

Parish output is stored in:

  src/features/ar-navigation/maps/parish/assets/

House output is stored in:

  src/features/ar-navigation/maps/house/assets/

The generator creates marker SVGs and markers-print.html. The house generator
also creates marker-placement-map.svg.

When adding a house marker, also add its index, x position, y position and
rotation to the arrows array in house/generateMarkers.mjs so it appears on the
house placement map.

Do not manually format generated files. The asset directories are listed in
.prettierignore because formatting markers-print.html breaks its exact embedded
SVG copies.


PART 6: RECOMPILE targets.mind
------------------------------

The .mind file must contain ALL marker images, not only the new image.

Use the MindAR Image Target Compiler that is compatible with MindAR 1.2.5.
Upload the generated marker images in exact numeric order:

Parish:

  marker-P00.svg, marker-P01.svg, ... marker-P17.svg

House:

  marker-H00.svg, marker-H01.svg, ... marker-H10.svg

If the compiler requires PNG or JPG, export every SVG to a 640 by 640 PNG
without cropping, recoloring, rotating or changing the artwork. Keep the exact
same numeric order.

Compile and download targets.mind, then replace the appropriate file:

  src/features/ar-navigation/maps/parish/assets/targets.mind

or:

  src/features/ar-navigation/maps/house/assets/targets.mind

Any marker artwork change requires recompiling the COMPLETE .mind file.


PART 7: UPDATE AND RUN TESTS
----------------------------

The tests intentionally protect marker count, order, destinations, facing and
compiled target count. Update the applicable expectations when adding a marker:

  src/features/ar-navigation/services/parishFacing.test.mjs
  src/features/ar-navigation/services/parishMarkers.test.mjs
  src/features/ar-navigation/services/parishNavigation.test.mjs
  src/features/ar-navigation/services/checkpointNavigation.test.mjs
  src/features/ar-navigation/services/targetFile.test.mjs

Then run:

  cd frontend

  node src/features/ar-navigation/maps/parish/generateMarkers.mjs --check
  node src/features/ar-navigation/maps/house/generateMarkers.mjs --check
  node --experimental-strip-types --test src/features/ar-navigation/services/*.test.mjs
  npm run lint
  npm run build

All checks must pass before deploying.


PART 8: PRINT, INSTALL AND FIELD-CHECK
--------------------------------------

1. Print markers-print.html at 100 percent scale and in color.
2. Do not crop, laminate with strong glare, rotate or resize individual marker
   artwork.
3. Mount the marker flat and away from moving doors or obstructions.
4. Stand on the documented scanning side.
5. Confirm the marker is recognized as the correct location.
6. Test routes from the marker and routes arriving at the marker.
7. Check left, right, straight, turn-around and destination confirmation.
8. Test the route in both directions when the path is bidirectional.


MAIN CHURCH EXAMPLE
-------------------

The Main Church addition followed this process:

  nodeId: c_church
  destination ID: main-church
  marker code: P16
  target index: 16
  facing: 0 (up the floor plan)

P16 was appended after P15, the 17 SVGs and print pack were regenerated, and
the parish targets.mind file was recompiled with all 17 images.
